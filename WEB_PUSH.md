# Web push notifications (browser)

Tether can send notifications to a partner's **browser** (hug / kiss / miss-you /
"thinking of you", the SOS alert, and new moments) even when the tab is closed —
using Firebase Cloud Messaging (FCM). Native iOS/Android push is separate and
already works via Expo; this doc is only about the **web/PWA** side.

Nothing here changes the app's data model or security rules. It adds:

- a browser push registration (`src/services/webPush.ts`),
- a service worker emitted into the build (`dist/firebase-messaging-sw.js`, generated by `scripts/setup-pwa.mjs`),
- a Cloud Function sender (`functions/`) that delivers the push when a ping / SOS / moment is written to Firestore.

Until you complete the two setup steps below, web push stays **off** and the app
behaves exactly as before (no errors, the "enable alerts" card simply doesn't
appear on web).

---

## One-time setup

### 1. Add the VAPID key (enables the browser to subscribe)

1. Firebase console → your project (**tether-aee5d**) → **Project settings** →
   **Cloud Messaging** tab.
2. Under **Web Push certificates**, click **Generate key pair**.
3. Copy the key string and paste it into `src/config.ts`:
   ```ts
   export const fcmVapidKey = 'PASTE_THE_KEY_HERE';
   ```

### 2. Enable billing + deploy the Cloud Function (enables sending)

Cloud Functions require the **Blaze (pay-as-you-go)** plan. Cloud Messaging
itself is free; for two people the function usage is comfortably within the free
tier — you're enabling Blaze only because Functions requires it.

1. Firebase console → **Upgrade** → Blaze (you can set a low budget alert).
2. From the project root:
   ```bash
   npm install -g firebase-tools   # if not already installed
   firebase login
   npm run deploy:all              # builds web + deploys hosting AND functions
   ```
   (Or deploy pieces individually: `npm run deploy` for hosting only,
   `npm run deploy:functions` for the function only.)

That's it. On next visit, open **Miss you** → tap **Enable alerts**, allow the
browser prompt, and the browser is registered.

## How it fits together

- On web, `registerForPush()` (in `src/services/push.ts`) branches to
  `registerWebPush()`, which asks permission, registers the service worker, and
  mints an **FCM token**. `AppContext.enablePush()` stores it in the shared
  space's `tokens` collection as `{ kind: 'fcm', owner: <userId>, … }` with a
  `${userId}:web` doc id (so a phone token and a browser token never collide).
- Native devices are still notified **client-side** via Expo push, exactly as
  before. The Cloud Function only targets `kind: 'fcm'` tokens, so there is no
  double-notify.
- When a `pings` / `alerts` / `moments` doc is created, the function sends a
  **data-only** message to the partner's browser token(s); the service worker's
  `onBackgroundMessage` renders exactly one notification and focuses the app on
  click.

## Caveats (browser platform limits, not bugs)

- **iOS**: web push only works for an **installed** PWA (Add to Home Screen) on
  iOS 16.4+. In a regular Safari tab it won't fire. Android/desktop Chrome &
  Edge work in a normal tab.
- A browser that has revoked notification permission won't receive pushes until
  re-granted (site permissions in the address bar).
- For the most reliable "reach me while asleep" SOS alarm, the **native app** is
  still the strongest path.

## Verifying it works

After setup, in two browsers (or two devices) signed into the same space:
send a hug from one → the other should get a system notification within a few
seconds even with the tab backgrounded. If nothing arrives, check:
`Firebase console → Functions → logs` for `onPing`, and that the recipient's
`tokens` doc has `kind: 'fcm'`.
